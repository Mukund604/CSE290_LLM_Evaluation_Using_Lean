# Evaluation harness

Lean 4 + Mathlib harness for verifying candidate proofs against the
30-problem miniF2F-v2 subset (see `../subset.md`).

## Layout

```
harness/
  README.md                  # this file
  problems/                  # generated; one .lean per subset problem
  problems_perturbed/        # generated by perturb.py; alpha_rename/, hyp_reorder/, restate/
  scripts/
    fetch_dataset.py         # pull miniF2F-v2 JSON into ../datasets/
    build_problems.py        # write per-problem template .lean files
    parse_errors.py          # classify Lean stderr into taxonomy categories
    run.py                   # batch verifier: model output JSONL -> result JSONL
    generate.py              # call model APIs; --condition baseline|informal_sketch
    perturb.py               # build alpha-rename / hyp-reorder / restate variants
    aggregate.py             # results JSONL -> pool pass rates and breakdowns
    shape_compare.py         # human vs model proof shape analysis
    coding_sheet.py          # sample failures for hand-coding; merge codes back
    human_baseline_to_jsonl.py  # human_baseline/problems/*.lean -> run.py input
  results/                   # per-run output JSONL (gitignored except .gitkeep)
```

Toolchain is pinned in the repo root:

- `lean-toolchain` — `leanprover/lean4:v4.30.0`
- `lakefile.lean` — Mathlib at master (pinned via `lake-manifest.json` after
  first `lake update`)
- `MiniF2FEval.lean` — single `import Mathlib` cache primer

## First-time setup

```bash
# 1. Install elan if you haven't (https://leanprover.github.io/).
# 2. Materialize and pin Mathlib:
lake update
git add lake-manifest.json && git commit -m "Pin Mathlib"

# 3. Prime the build cache. This is the long step (~30 min first time).
lake build

# 4. Pull the miniF2F-v2 dataset:
python3 harness/scripts/fetch_dataset.py

# 5. Generate per-problem templates:
python3 harness/scripts/build_problems.py
ls harness/problems     # should show 30 .lean files
```

## Verifying model outputs

Input is JSONL, one row per (problem, candidate proof, model, seed,
condition):

```jsonl
{"problem":"mathd_algebra_22","proof":"  exact by norm_num [Real.logb]","model":"claude-opus-4-7","seed":0,"condition":"baseline"}
{"problem":"imo_1964_p1_1","proof":"  intro h\n  ...","model":"gpt-5.2","seed":0,"condition":"baseline"}
```

The `proof` field is the body of the `by` block — everything the model
would write after `:= by`. The runner indents it and substitutes for the
`sorry` placeholder in the template.

Run:

```bash
python3 harness/scripts/run.py \
    --input  attempts/claude_baseline_seed0.jsonl \
    --output harness/results/claude_baseline_seed0.jsonl \
    --jobs 4 --timeout 180
```

Output rows look like:

```jsonl
{"problem":"mathd_algebra_22","model":"claude-opus-4-7","seed":0,"condition":"baseline","passed":true,"duration_s":3.4,"category":"passed","stderr_excerpt":""}
{"problem":"imo_2006_p3","model":"claude-opus-4-7","seed":0,"condition":"baseline","passed":false,"duration_s":42.1,"category":"heavy_tactic_failed","stderr_excerpt":"polyrith failed ..."}
```

## Smoke test before main runs

To confirm the harness is wired correctly *before* spending model budget,
verify the human-baseline proofs against the same harness:

```bash
python3 harness/scripts/human_baseline_to_jsonl.py \
    --in-dir human_baseline/problems \
    --output harness/results/human_baseline_input.jsonl

python3 harness/scripts/run.py \
    --input  harness/results/human_baseline_input.jsonl \
    --output harness/results/human_baseline_results.jsonl \
    --jobs 4
```

Every accepted human proof should report `passed: true`. Any `passed: false`
in this run is a harness bug or an as-yet-unverified human submission.

## Error taxonomy seed categories

`parse_errors.py` produces a coarse first-pass label per failure. These
are the buckets the hand-coding pilot starts from; expect them to fork
and merge as the failure-coding pilot batch accumulates evidence.

| Category | Trigger |
|---|---|
| `hallucinated_lemma` | unknown identifier / constant / tactic |
| `type_mismatch` | "type mismatch" / "has type ... but is expected" |
| `unfocused_goals` | "unsolved goals" / "no goals" |
| `heavy_tactic_failed` | `nlinarith` / `polyrith` / `omega` / `decide` / `positivity` failure |
| `tactic_failed` | Any other named tactic (`rfl`, `ring`, `simp`, …) reported failure |
| `syntax_error` | parser errors |
| `timeout` | exceeded `--timeout` |
| `sorry_present` | proof still contains `sorry` |
| `other` | nothing matched yet |
